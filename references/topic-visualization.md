# 推荐时默认可视化

本规则由使用方 `visualization_policy.default_for_topic_requests=true` 启用；未配置账号不强制改变表达。普通推荐、每日雷达、候选筛选、周排期、续推与修订都适用；用户当次明确只要文字优先。

先完成选题判断和证据记录，再呈现推荐。优先解析当前可用 `visualize` Skill 并完整读取它，按其合同在当前回复展示交互视图。未提供该能力时用 Mermaid 展示任务与方法关系，并用简短卡片补候选详情；不能把未渲染的代码或文件路径说成已展示。

推荐几题就呈现几题；不因画图扩增候选。默认是可选择的候选列表与一份选中详情：帮谁完成什么、观众入口及输出、网格组合、为什么本人能讲、已有证据/待测项、半天备料动作、最近相似作品与新差异、可录/先测/观察状态。题目有真实评分时标口径；不用装饰性雷达分或爆款概率。

卡详情按 [七模型拆解](04-topic-template.md) 展示原问题/当前做法、价值诊断及处理、阅读/分享理由、五个入口及采用理由、承诺与材料对应、可无系列位置、一个复盘假设。列表保留主要收获和缺口，标题备选与内部检查可折叠；完整卡不能只显示标题/分数。旧记录缺topic_analysis时显示未拆解，不伪造通过状态。数据来自原candidate及其投影，不在图里另存可编辑卡；UI字段兼容性未实测时如实报告，可用宿主交互视图/文字详情呈现，不宣称现有后台已增加界面。

九宫格策略请求呈现两张完整3×3图，中心不作为第九分类。日常推荐可用网格位置或组合标签标来源，不反复展开策略长文。运营请求增加反馈闭环和数据覆盖视图。任何缺失、来源过期、观测窗口不匹配都需可见，不能在图中补造数字。

展示内容来源于 `topics/`、作品 `work.json`/`distribution` 与 `research/` 的已验证记录；保留稳定topic/work/platform IDs和证据路径。交互选择默认只改变展示；真正选中需用户明确请求后调用使用方 topics-pick。不能因点击网格、推荐高分或定时运行自动建作品。

每次回复实际附上可见图，而不是只登记“visualized=true”。运行记录保存数据投影、源版本、图路径、生成时间、未验证项；图的技术验收与用户认可分别记录。每日无新证据时复用已有待选视图，保持安静，不假装又发现了新题。
