# 发布结果回到下一轮选题

本模块可立即使用，无需等待另一套系统上线。先读取作品work.json、distribution事件与用户提供的数据；不编造没有接入的后台指标。

记录work_id、topic_id、平台、观测起止、象限、任务、CTA、指标分母和证据路径。Q1关注非粉触达/分享；Q2关注收藏/搜索/步骤提问/实际复用；Q3关注资产使用/有效需求；Q4关注持续关注及身份共鸣。

成交、报价、范围讨论与播放点赞分别记录。不存在的数据留空，不写0。按相同平台和观测窗口比较，避免老作品累计量与新作品早期量直接比较。

每次形成 keep / revise / collect_evidence / pause 决策及原因，回写同一作品。下一轮选题先读这些决策，避免只追当期热榜。调整频次、栏目、商业路径是实验变更，记录认可依据，不自动改写账号长期定位。

## 从选题卡核对承诺与反馈

先读取原选题卡的topic_analysis.review_plan与promise_chain，核对实际采用标题、开头、正文交付和CTA是否改变；保留五个备选及采用理由，关联实际发布版本，未采用者没有表现数据。没有预设目标的历史作品标未知，本次可以形成新的假设，不能倒填成发布前计划。七模型的卡定义由 [选题卡拆解](04-topic-template.md) 持有。

表现好时分别问：哪个问题吸引了人、哪份材料提供了价值、哪个表达值得在相邻问题再试；逐项写观察证据或待验证解释，不把它们合成已验证因果。表现一般时先核查有没有可观察数据，再确定是测试入口、补交付还是补证据。每轮只选一个主要改动假设，记录保留因素、实际差异、同口径窗口及下一次查看条件；低点赞不能证明读者没有看完，高收藏不能证明操作成功。

系列下一题必须解决独立任务并产生新差异，继续引用相邻作品的材料/反馈；不要为复用好标题重复同一命题。标题的类型、适用条件和反馈可从原卡/作品检索，不另建第二套标题权威库。下一轮筛选把这些观察回到需求依据、材料计划或入口测试，遵守既有去重和用户选择边界。

## 先检查数据能否支撑决策

先运行 `python3 <engine>/scripts/operations_audit.py --root <作品工作区> --account <明确别名> --data-root <该账号数据目录> --as-of <带时区ISO时间> --output <研究运行目录/coverage.json>`。工具只读台账和原始数据，按平台作品ID合并同账号重复记录，检查索引路径、数据新鲜度、作品对应与发布后24/72/168小时的观测覆盖；不按标题关联、不修平台数据、不自动做内容质量评分。缺值、未知来源、重复ID、窗口外样本会保留缺口。

采集复用已安装的 `moonlit-douyin-extractor` 或正式平台能力，先确认显式账号、身份探针和输出归属。记录 success/partial/unavailable/failed/not_called；已绑定不等于采集通过。既有有效数据可继续使用，但过期数据只做历史参照。登录过期/身份不匹配停止该源，保留完成部分，等真实恢复后续跑；不覆盖或制造零值。

## 复盘给人看，故障先解决

给用户的复盘先写三件事：这周实际完成了什么、哪项数据说明什么、接下来做什么。用作品名和原始数量，必要时解释“收藏/播放”；keep/revise/collect_evidence/pause、样本口径和审计字段保留在结构化记录或附录，不要求用户先懂这些词。下一步最多三项，每项写清谁做、做完能看到什么；没有实测不写成果。

发现采集器漏读新接口、把缺字段填零、或把尝试数当完成数时，先停用该路错误结果，定位、修复并真实读回，再更新其影响的复盘。不能只列缺口后继续评价内容好坏，也不能把程序漏采归因为观众没有反馈。正常的真实零评论、还没到观测窗口、独立渠道登录限制仍如实记录；其他可靠来源可独立推进，不扩大或绕过登录授权。

## 用同口径的观测

- 单元是同一账号的一次平台发布，不能把82个跨平台已发布作品当成82条抖音样本。多形态从作品关联，计数时分开。
- 保存发布时间、实际capturedAt、来源、字段口径、累积或区间性质。目标24/72/168小时只是采样计划；显示实际发布年龄与预设容差，窗口未采到就写missing，不能从后来的累计量倒推早期值。每日回流可捕捉窗口；离线错过的仍缺失。
- 收藏、分享等比率只在真实播放分母大于0、同一快照且来源一致时计算；保留分子分母。0播放不能除，缺字段不补0。完播、停留、净增粉、搜索、主页访问、咨询、成交没有接入就留空。互动次数不一定是独立人数，不能当独立用户试验算显著性。
- 比较同平台/账号/统计定义/发布年龄窗口，尽量控制题型、视频长度、分发渠道、付费投放与节假日；这些未知时标未知。按作品给中位数、范围与样本数，避免一条爆款决定长期定位；不设通用优秀率阈值。
- 数据只能定位待查环节。低播放不直接证明选题错；收藏不直接证明教程已被使用；高点赞不证明开头或剪辑造成增长。步骤提问、尝试反馈与失败评论的去标识摘要形成下一轮具体任务，并保留评论来源及不完整状态。

## 四项可独立恢复的运营职责

1. 数据回流：更新明确账号的指标/评论，检查作品ID对应、新鲜度和缺口，输出覆盖报告。
2. 选题推荐：读最新覆盖、复盘、用户选择与拒绝；以观众任务×行业能力召回，结合作者材料、当前线索与预算，交付请求数量及可视化。没有新证据不硬凑新题。
3. 已选作品备料：仅处理用户pick或明确委派的活跃作品，按使用方并行上限推进零新增费用的研究、验证计划、材料与讲解提纲；完整成稿/制作读取各阶段Skill。输入未变就复用，重复运行不建副本。
4. 周复盘：先检查窗口与样本可比性，再给keep/revise/collect_evidence/pause及一项下周实验。没有充分样本则补证，不输出“规律已验证”。

任务数、时间、平台、预算、产能及授权读使用方运营配置；Skill不设日更或固定题材比例。自动化用宿主正式调度工具，先查重；每路失败不阻断另一路。运行记录以job+日期/作品输入指纹幂等，保存输入、结果、下一步、证据与缺口，不因计划成功报告采集/实测/发布成功。

## 持续实践而不是追一条爆款

先记录假设、具体改动、主指标、辅助指标、对照范围、观察窗口、混杂因素、制作耗时和停止/扩展条件。有限产能可每轮只改一个主要因素以方便解释，这是运营折中；不同作品仍有题材/时段/分发差异，不能称随机A/B或因果验证，也会漏掉因素交互。[NIST实验设计说明](https://www.itl.nist.gov/div898/handbook/pri/section2/pri212.htm)

少量作品先当案例观察，反复出现且具真实使用反馈再扩大同类任务；记录总耗时、实测成功/失败、小白复现入口、可复用素材。周发布量是有证据后调整的容量，不是流量目标；增长、观众完成任务和作者可持续性一起判断。未经用户选择不建作品，未经当前明确授权不发布、购买或改长期定位。
