# 观众场景与行业方法的双九宫格

仅在用户明确要求九宫格发散、重建主题矩阵或开展全局覆盖研究时使用。普通日常选题默认使用 `evidence-led-selection.md`；网格用于辅助发散，不是出题前置条件，不覆盖当前定位、评论需求或证据筛选。它不替代人群判断、证据核验或选题决策。

参考：[薛辉小清新《持续创作的秘密》](https://www.douyin.com/video/7512826969394957583) 的双九宫格方法。原视频还提出从客户提问、同行评论与行业资讯积累素材；其中对流量与账号成功的保证不作为规则。下述证据标记、实测队列与版本管理是本 Skill 的落地设计。

## 四种材料分清角色

- **观众网格**：观众的兴趣、处境、任务或想得到的结果。格子附实际提问/观察来源，或明确标 agent_hypothesis。没有评论不能说有高频需求。
- **行业网格**：行业能提供的能力、方法、工具和素材。原始文档证明能力，不证明中文观众能用；实际入口另行核验。
- **作者材料**：人生事件、当前兴趣、真实作品与能力，用来决定作者凭什么讲、能提供什么案例。作者兴趣不自动进入观众网格。
- **选题角度**：案例、方法、取舍等表达视角。已有 topic_grid 框架先查看角色，不能把八个表达角度称为受众与行业的双网格。

中心、外围、格子数量都可调整。用户要求完整九宫格，且已有定位、作品、项目或相关研究足够时，Agent 应综合材料完成两侧各八个外围格，并说明作者依据与具体任务；不能仅因尚无逐格确认或最新评论就交付通用模板与空位。格子可作为有依据的编辑提议，观众需求强弱仍按实际证据标注，不冒充已观察需求。确实没有材料时才保留空位或缺口，不编造经历。

每项携带稳定 ID、角色、来源归属与版本。具体格词与账号优先级留在使用方配置。用户已维护的网格只读取和补缺；用户要求重做时保留旧版并升级当前版本，不悄悄覆盖历史。热点作为各格的新线索，不因每次发布就重写稳定网格。

## 组合与召回

历史配置可保留 `selection_method.mode=paired_grids`，但此方法不再被普通请求自动触发。用户明确要求网格时，配置中的 `paired_grids.status` 与 approval 记录用户认可的版本与范围；认可策略和八格，不等于认可所有组合、实测结果或发布。原始作者归属和观众需求证据保留，不能因认可而改写成亲历事实或高频需求。

### 从材料到持续出题

1. **读取当前人群与网格。** 同时看近期命题、选择/拒绝反馈、作者材料索引和可用预算。已有认可网格则复用；要重做时先看真实作品/项目与人生材料，再完成两张完整图。只有材料会改变本轮判断时才扩展读取，不把全部人生史注入上下文。
2. **从任务或新线索双向发散。** 可以由观众问题找到行业方法，也可以把一项新能力映射到已有观众任务。选少量有明确关系的组合；主题簇中的 grid_pair 是召回起点，不限制只能用那一对。单条候选可以选其他真实格子，但必须说明关系。
3. **用本人材料形成可信讲法。** 对入围组合找到一段自己的输入、制作过程、作品、项目决定或可执行实验。解释它支持什么结果，以及相对旧内容增加了什么。对标提供问题和表达结构，不提供可冒用的作者经历。
4. **定向补来源。** 按本轮启用来源与召回预算，让 moonlit-topic-radar 补相关线索；近期、仍有用和常青/本人现场都可进池。热点补时机、解法或反例，不覆盖稳定网格或人群。来源未调用、不可访问、调用失败分别记录。
5. **先把结果写具体，再筛可录性。** 每题一个任务、一个主要收益，给出输入、入口、步骤、输出、验收、成本和必要条件；复杂链路由作者承担。实际结果与计划测试分开，根据准备预算进入可录、先测、储备或观察；再做命题/案例/证据去重。
6. **小批选择并学习。** 按用户数量和配置 mix_policy 取舍，不为了八格或象限齐全凑题。记录选中、拒绝原因、实测完成、作品去向和发布反馈。新增证据可更新候选，只有用户改变长期方向时再调整当前网格；不从一次点赞或一次测试推断人格和固定频率。

当前 Agent/可配置模型先理解一对格子之间是否有真实任务关系，解释关系、标相关来源和未知，不用关键词计分替代判断。普通几题请求只提出所需组合；用户明确要求完整组合的每日多候选池时按 daily-topic-pool.md 逐组审读并维护覆盖，不按乘积模板换标题凑数。

组合记录 `audience_cell_id`、`capability_cell_id`、`grid_version`、`relation_reason`；来源召回由 moonlit-topic-radar 按这些已审读任务规划。查询只用适当公开的任务词，不把人生原始材料、聊天与客户信息送进公开搜索。

context 保存当前 selection_method；配置 require_grid_pair=true 时，rank 不接受缺少配对的已审读候选。格子角色、版本和关系理由仍需核对，未审读的条目只能留 unreviewed。程序负责引用与门槛，语义关系由 Agent 判断，不能用“字段通过”代替内容适配。

例如“汇报场景 × 信息整理”只形成待测问题；具体题还需限定输入、交付物、工具入口和验收。换场景或换工具不足以证明命题不同；沿用 personalized-selection 的语义去重与拒绝反馈检查。

## 实用任务契约

当账号配置 `profile.audience_contract.practical_required=true`，rank 前增加 `audience_review`：当前 `contract_version`，模型/作者给出的 `audience_fit` 与 `practical_fit`（pass/fail/unknown）、reason、viewer_task、input、steps、output、verification，以及 viewer_entry 的 status（verified/planned/unknown）、instructions、prerequisites、cost、language。没有前提可写“无需额外安装”，不能空着当默认。

`demand_basis` 包含 kind（user_request/observed_question/agent_hypothesis）、detail；前两类引用本轮可用 evidence_ids。observed_question 还需真实 `audience_question` 材料，不能引用兴趣提议证明需求。假设可选题和测试，不能写成已观察需求。观众入口 planned 时必须给 test_actions，只能先测；unknown 或字段缺失留 observe。作者有一手结果仍不能证明观众入口可用。

代码只落实明确语义判定、引用、字段、版本和队列约束。高分、热点、作者兴趣不能覆盖 fail。账号受众配置变更必须重组 context 并重审；禁止给旧审读直接改 hash。已拒同命题需说明实质变化和新证据才可复提。

非实用任务请求（解释、叙事等）仍按内容首要原则判断，不能把本模式强制扩展到所有账号或所有作品。
