# 账号矩阵速查骨架

> ⚠️ **本文件只描述账号矩阵的查询路径**。具体账号数量、分工、禁忌 → 每次调用前**动态读知识库 01-账号战略与IP定位/账号矩阵定位.md** 获取。

**辅助路径**：

## 通用方法（不依赖具体账号）

任何业务的账号矩阵通常包含 3 类角色：

1. **个人信任入口**：以个人 IP 为核心，承担长期信任
2. **企业成交入口**：以公司/品牌为核心，承担商业转化
3. **实验/合作入口**：以测试/合作为核心，承担探索性内容

**注**：具体账号数 = 1/2/3/N，取决于业务，不在本文件写死。

## 选题分配原则（通用）

```
1. 每条内容先写"服务哪个角色、完成什么任务"
2. 根据角色选账号
3. 同一母项目可在多账号分发，但开头/证据/CTA 必须不同
```

## 禁忌原则（通用）

任何账号矩阵都有 3 类禁忌：
1. **个人号不做直接卖货**
2. **企业号不写个人私事**
3. **实验号不卷入行业口水战**

**注**：具体禁忌细则 → 知识库 01 动态读取。

## 选题分配决策树（通用骨架）

```
开始
  │
  ├─ 这条选题讲"个人判断/取舍/过程"？
  │    → 个人信任入口（默认）
  │
  ├─ 这条选题讲"客户案例/交付/服务"？
  │    → 企业成交入口
  │
  ├─ 这条选题讲"产品测试/适配/合作"？
  │    → 实验/合作入口
  │
  └─ 不确定？
       → 默认个人信任入口（大号主战场）
```

## 形态适配原则（通用）

```
个人信任入口 → 长文 + 短视频 + 朋友圈
企业成交入口 → 长文 + H5 + 落地页
实验/合作入口 → 小红书 + 漫画 + 短视频
```

**注**：具体形态禁忌 → 知识库 01 + viral content-formats 动态读取。

## 母项目拆分规则（通用）

同一母项目（一条核心选题）拆多账号版本时，3 个要素必须不同：

| 要素 | 差异方向 |
|---|---|
| 开头 | 个人观察 vs 客户痛点 vs 产品测试 |
| 证据 | 内部判断 vs 脱敏案例 vs 测试数据 |
| CTA | 私信/扣词 vs 扫码/咨询 vs 加群/试用 |

具体话术 → 知识库 05 动态读取。

## Pitfalls

- ❌ 把具体账号数量和分工写进本文件——业务改账号矩阵就要同步
- ❌ 不读知识库 01 直接给账号分工——可能用过期版本
- ❌ 同一选题复制到多账号——失去账号差异化
