# 单条选题卡

每次填写先读 [七模型拆解](../references/04-topic-template.md)。普通推荐与待确认详情用完整卡，每日大池可先用简卡并记录待补。内部判断不必全部展开，但不能以隐藏字段掩盖缺口。未选题留topics，用户选中后再通过工作区topics-pick关联作品。

```markdown
## [采用/暂定标题]

- 身份与状态：[topic_id、日期、Q1/Q2/Q3/Q4；简卡/完整卡；可录/先测/储备/观察]
- 来源入口：[定位 / 本人评论 / 对标评论 / AGI Hunt；主来源、采集/发布时间、证据链接及范围]
- 帮谁、什么处境：[content_brief中的具体人和场景]
- 原问题与依据：[评论题保留真实原话/准确摘要、作品与评论ID；注明单条或可核验频次；非评论题注明证据/假设]
- 定位连接：[当前目标用户的产品化、营销、获客或转化任务；月明的真实讲法]
- 当前怎样处理、本篇帮助哪一步：[当前做法；一个主要收获及边界]
- 价值诊断：[读者/作者出发 × 材料支持/可测/缺交付；继续/换入口/补交付/暂缓及理由]
- 看完与分享理由：[主需求、可无的辅助需求；为什么看完，可能分享给谁用于什么；标观察/假设/弱/无]
- 双九宫格配对：[启用时记格子名称及任务关系；数据保留cell IDs、grid_version]
- 本人凭什么讲：[真实作品/经历/材料支持什么；或具体可执行实验]
- 为什么现在做：[事实日期与时效，或当前任务；不硬凑热点]

### 五个入口，仍然是同一个题

| ID | 入口类型 | 标题 | 五项核对及状态 |
|---|---|---|---|
| H1 | […] | […] | [看懂/具体/兑现/数字/一致；pass/revise/pending_evidence，理由] |
| H2 | […] | […] | […] |
| H3 | […] | […] | […] |
| H4 | […] | […] | […] |
| H5 | […] | […] | […] |

- 采用：[H?及理由；只有待测承诺时写暂定，不造实绩]
- 钩子—交付—下一步：[各一句；下一步可自然结束/无CTA]
- 大纲与材料位置：[入口、处境/关切、解释、证据、收束；按内容调整顺序，不强制五段]
- 观众怎么做：[实用任务填输入、入口、步骤、输出、验收、费用/前提；其他形态不强制]
- 来源与证据状态：[原始来源/日期/读取范围、支持哪项承诺；已核验/待核验/计划测试]
- 测试、补证与预算：[当天做什么、支持/推翻条件、预计备料时间、可见证据；未做不称完成]
- 去重：[已查范围、近期近似题、至少两项实质差异或缺口]
- 筛选：[推荐理由、保留/观察原因；如评分，使用当前百分制及限制]
- 可选CTA、承接假设：[入口就绪状态；均可无]
- 系列位置：[可无；本篇独立任务、邻题ID与新增差异，不预设篇数]
- 复盘预设：[一个主目标、可用信号/不可观察项、窗口、一个待验证假设及下轮主要改动]
- 待补项：[具体缺口；没有则空，不把完整卡当成已实测/用户认可]
```

content_brief字段按当前激活 moonlit-business-copywriter 的 content-first-principles；topic_analysis字段由七模型拆解持有。评分采用当前 moonlit-topic-radar 的quadrant-scoring：台账不完整最高79，不新增爆款指数。只在用户要求排期或多形态时增加安排。

已选作品保留原卡；后续采用的入口及实际表现回写同一作品，按 [数据闭环](../references/07-data-loop.md) 和 [复盘模板](data-replay.md)，不为了标题备选另建作品。规则缺陷另走 moonlit-skill-creator 的experience-loop，内容表现不自动升级为Skill规则。
